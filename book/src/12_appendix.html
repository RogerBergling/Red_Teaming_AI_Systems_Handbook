A. Building the lab

The lab is deliberately small. It runs on one Linux host with 32 GB of RAM and a modern CPU; a GPU is helpful but not required if the model is quantised and small. Everything is local: no cloud accounts, no external model APIs, no real data.

Host and network

RequirementRecommendation
Operating systemLinux with Docker Engine 26+ or Podman 5+, and Compose v2
Memory32 GB minimum; 64 GB if running a 7B model unquantised
Disk100 GB free; model weights dominate
NetworkAn isolated bridge network with no route to the internet and no route to the host LAN. DNS resolves only *.lab.local.
ModelA 3–8B instruction-tuned open-weight model, quantised. One model is enough; a second small model is useful for the dual-LLM exercise.
Attacker servicesA mock collector, a mock web server and a mock metadata service on the lab network

Compose skeleton

    driver: bridge
    internal: true          # no route out
services:
  inference:
    image: ollama/ollama
    networks: [lab]
    volumes: ["models:/root/.ollama"]
  vectors:
    image: qdrant/qdrant
    networks: [lab]
  agent:
    build: ./agent
    networks: [lab]
    environment:
      MODEL_URL: http://inference:11434
      QDRANT_URL: http://vectors:6333
    volumes: ["./sandbox:/sandbox"]
  mock-web:
    build: ./mock-web
    networks: [lab]
  collector:
    build: ./collector
    networks: [lab]

Safety checklist

  • The lab network has no default route and no NAT to the internet.
  • No real API keys, cloud credentials or personal data are mounted into any container.
  • The agent's http_get tool can reach only mock-web and collector.
  • Payments and emails are mock services that log to the collector.
  • Every container runs as non-root with a read-only root filesystem where possible.
  • A reset.sh recreates volumes, indexes and memory from seed data.
  • Logs are retained for the course and destroyed afterwards.

Harness over heroics

A 200-line harness that records assembled prompts, tool calls, seeds and judgements is worth more than a dozen clever one-off payloads. Build it once, reuse it for every module, and keep the raw logs.

D. Telemetry schema

A minimum viable record for an AI interaction. Emit one event per model call and one per tool call, linked by trace_id. Redact at the edge, not in the warehouse.

{
  "ts": "2026-10-28T09:14:03.221Z",
  "trace_id": "3f9c...",
  "session_id": "s-8821",
  "principal": {"type": "user", "id": "u-1042", "tenant": "t-07"},
  "agent": {"id": "claims-orchestrator", "version": "1.4.2"},
  "model": {"provider": "internal", "id": "llama-3.1-8b", "revision": "sha256:...", "temperature": 0.2},
  "prompt": {
    "system_hash": "sha256:...",
    "assembled_hash": "sha256:...",
    "assembled_ref": "s3://logs/...",
    "retrieved": [{"chunk_id": "d-331#4", "source": "policy.pdf", "score": 0.81, "acl": "tenant:t-07"}]
  },
  "decision": {"type": "tool_call", "tool": "issue_refund", "args": {"amount": 240, "account": "a-99"}},
  "authorisation": {"decision": "allow", "policy": "refund<=250", "approver": null},
  "result": {"status": "ok", "latency_ms": 812},
  "egress": {"destination": "ledger.lab.local", "allowed": true}
}

Store the assembled prompt by reference, not only by hash: reproduction requires the text. Encrypt the store, restrict access, and set retention. The log is now one of the most sensitive datasets in the organisation.

E. Glossary

TermDefinition
A2AAgent2Agent protocol for interoperability between independent agents; agent cards, tasks, messages and artifacts.
Adapter (LoRA)A small set of weights that modifies a base model's behaviour without retraining it fully.
AgentA model plus a loop, memory and tools, able to take actions toward a goal.
Agent cardMachine-readable metadata describing an A2A agent's skills, supported interfaces and security schemes.
ASRAttack success rate: proportion of trials in which the objective is achieved.
AttentionThe transformer operation in which each position computes query, key and value vectors and mixes information from other positions according to their similarity.
BackpropagationReverse-mode differentiation through a neural network; computes the gradient of the loss with respect to every parameter in one backward pass.
BPEByte Pair Encoding: a subword tokenisation method that repeatedly merges the most frequent adjacent symbol pair to build a fixed vocabulary.
ChunkA segment of a document stored and embedded for retrieval.
Confused deputyA component with authority that is tricked into using it on behalf of a less-privileged party.
Context windowThe maximum number of tokens a model can process in one call.
DPODirect Preference Optimisation: preference tuning that optimises a policy directly on chosen/rejected response pairs without a separate reward model.
EmbeddingA vector representation of content, used for similarity search.
GradientThe vector of partial derivatives of a loss with respect to model parameters or inputs; the signal used for training and for gradient-based adversarial examples.
GuardrailA control that inspects or constrains model input, output or actions.
Indirect prompt injectionInstructions delivered through content the model reads, rather than through the user's message.
Instruction hierarchyThe learned precedence of system, developer, user and tool content.
KV cacheStored key and value tensors for previously processed tokens, reused during generation to avoid recomputing attention.
Lethal trifectaPrivate data access + untrusted content + outbound channel in one agent.
LogitsThe unnormalised scores a model produces for each vocabulary token before softmax converts them into probabilities.
LoRALow-Rank Adaptation: parameter-efficient fine-tuning that learns a low-rank update BA to a frozen weight matrix.
MCPModel Context Protocol: JSON-RPC standard for exposing tools, resources and prompts to a model host.
Membership inferenceDetermining whether a specific record was part of a dataset or index.
PerplexityThe exponentiated average negative log-likelihood of a token sequence; a measure of how well a model predicts text.
PicklePython serialisation format capable of arbitrary object reconstruction; unsafe loaders can execute code on load. PyTorch 2.6+ defaults torch.load to weights_only=True.
ProvenanceVerifiable information about where an artefact or piece of content came from and how it was handled.
QuantizationStoring weights or activations in lower numerical precision (for example INT8 or INT4) to reduce memory and compute, at some cost in accuracy or behavioural fidelity.
RAGRetrieval-augmented generation: injecting retrieved content into a model's context.
RerankerA model that reorders retrieval candidates by relevance.
RLHFReinforcement Learning from Human Feedback: training a reward model on human preferences and optimising a policy against it, usually with a KL penalty.
Rug pull (MCP)Changing a tool definition or behaviour after the user has approved it.
SBOM / AI-BOMInventory of software / AI components, versions, licences and provenance.
SafetensorsA tensor serialisation format that does not execute code on load.
Sampling (MCP)A server requesting generations from the host's model. Deprecated in the 2026-07-28 revision along with Roots and Logging; still reachable during the deprecation window.
CIMDClient ID Metadata Documents: the client-registration mechanism preferred by MCP 2026-07-28, replacing deprecated Dynamic Client Registration.
SSRFServer-side request forgery: making a server fetch an attacker-chosen URL.
Taint trackingMarking data with its provenance and restricting how it may be used downstream.
TokenA unit of text produced by a tokenizer and mapped to an integer ID; the model's actual input and output unit.
TransformerA neural architecture built from attention and feed-forward blocks with residual connections; the basis of modern language models.
Tool poisoningEmbedding instructions in a tool's description or schema to influence the model.
Vector databaseA store optimised for nearest-neighbour search over embeddings.
Workload identityA short-lived, scoped identity issued to a running workload rather than a static key.

Closing note

The techniques in this handbook will age. Models will change, protocols will be revised, and today's default ports will be tomorrow's hardened endpoints. What will not change is the method: map the system, find where untrusted content meets authority, prove the path with evidence, measure it honestly, and leave the environment better instrumented than you found it. That is the job.
